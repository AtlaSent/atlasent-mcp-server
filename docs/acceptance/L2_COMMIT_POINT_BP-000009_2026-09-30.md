## What ran, and what was simulated

This is the shipped code, end to end:

```
MCP client → McpServer → atlasent_governed_file_change      (src/aiActionTools.ts)
  → requestAuthorization → engine.authorize                  (identity mint, provenance seal, evaluate)
  → awaitApproval → claim                                   (HOLD path)
  → executeGoverned                                          (verify at the boundary, execute once, observe the effect, emit proof)
  → githubFileAdapter                                        (src/githubFileAdapter.ts)
```

Exactly two things are simulated:

| Boundary | Simulation |
|---|---|
| AtlaSent runtime | A local HTTP server (real sockets, the engine's own `fetch`, no global patching) speaking the v1 wire. It mints an identity, seals provenance with the runtime's action-hash algorithm, decides by a scripted policy, and handles approvals and claims. It issues HMAC-signed, 300 s, single-use permits bound to action/actor/target/environment/hash, and refuses at verify with the runtime's own error codes. |
| Provider | An in-process GitHub contents API behind the adapter's `fetchImpl` seam. Every mutation call is counted. |

## The harness fails when the binding is broken

Each mutant must take effect (an `applied` counter is checked) and must fail at
least its target check.

| Mutant | Caught by |
|---|---|
| `verify_bypassed` | R5–R10, R12 |
| `payload_binding_removed` | R2, R5–R7, R9, R12, R13 |
| `replay_possible` (runtime never consumes) | R7, R8 |
| `deny_reaches_provider` | R11 |
| `execution_inferred_from_authorization` | R13b (both) |

Two mutations of the real source were also checked by hand, and each failed
the suite: replacing the verify call in `executeGoverned` with a constant
`valid: true`, and dropping `context.action_digest` in `engine.authorizeRemote`.
